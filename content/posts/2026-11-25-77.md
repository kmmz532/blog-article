条件式、isA && isB でisAが成り立たなくても
先回りしてisBも評価するコンパイラがあるかを調べてた。

たしか、投機的実行があったはずだと思い出した。
その場合、
arr: array = [...]; // 10まで値が入っている一次配列
i: int = -1;
b: bool = 0 <= i && i <= 10 && arr[i] == 0;
ならば、arr[i] == 0 を先回りしていたとして
安全装置が働くことが多く、エラーだとしても前の条件が評価できないならその評価の結果を放棄するやうだ。
(ISO/IEC 9899の6.5.13 Logical AND operatorより)
ただ、オレオレCコンパイラだったら動かない可能性はありそうだ。
また、一行が長くなりすぎるうえに、条件内容が別々なので
可読性の観点から改めて分けたほうがいいと思った。
