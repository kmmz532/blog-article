本日は大学のOBの方が研究室にて毎月開いている某m講座に9時から15時あたりまで参加した。

アウトプットができるってことはわかっているってこと。
この考え方はかなり腑に落ちた。

説明ができることは理解ができていることというのは前から思っていたが、アウトプットという表現で広くみてアウトプットすることだと感じた。

プログラミング講座ではpaizaを用いてFizzBuzzのコーディングをした。

かなりシンプルなC++実装にしたと思うが、Cばかり使っていたので、思わず、マクロの#defineを使っちゃった。
C++ではconstがあるのは知っていたが、普段からconstを使っていないので使い分けも考えたうえでこれから積極的に使おうと思う。

LegacyCとModernC/C++でかなり仕様が異なるんだと知った。

int main(); にしたが int main(void); にすることで引数を受け取らないことを指定できる。
もしくは引数を受け取るなら
int main(int argc, char* argv[], char* envp[]);
を使うほうがよさそうだ。

条件から前提条件や状況を考えることは難しいと感じた。

- main.h
```cpp
#include <iostream>

using namespace std;

void print(int min, int max);
```

- main.cpp
```cpp
#include "main.h"

// 定数についてマクロの #define でなく const を用いた。型が使える上、想定外の置き換えがないため。
const int MIN = 1;
const int MAX = 100;

// int main() は int main(void) と同様なことが多いが、暗黙的な仕様である、個人的にはvoidを書くのは他の言語をやってきた身としてあまり好まないので引数を置いた（使ってもよさそうだが・・・）
int main(int argc, char* argv[]) {
    print(MIN, MAX);
    return 0;
}

void print(int min, int max) {
    for (auto i = min; i <= max; ++i) {
        cout << i << " ";
        if (i % 3 == 0) cout << "Fizz";
        if (i % 5 == 0) cout << "Buzz";
        
        cout << endl;
    }
}
```
